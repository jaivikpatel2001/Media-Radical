# Media Radical — Premium IT Services Website (Phase 1: Home Page)

## Context

`media-radical/` is a clean `create-next-app` scaffold: **Next.js 16.2.12**, **React 19.2.4**, TypeScript, **Tailwind v4 installed**. Two commits, no custom code.

We are building a luxury, Apple-inspired IT services & consulting site. The full site is 17 page groups; **Phase 1 ships the Home page + `not-found.tsx` only**. The architecture must absorb the other 16 groups later with zero refactor — that constraint drives every structural decision below, especially the section-sharing and data-normalization choices.

Hard constraint: **no Tailwind, no utility-first CSS**. Tailwind is currently wired in and must be removed first.

**Approved decisions:** brand = *Media Radical* · **adaptive light + dark** theme · images generated by the user from prompts in §8 · build `not-found.tsx` in Phase 1.

### Next.js 16 constraints verified against bundled docs (`node_modules/next/dist/docs/`)

Per `AGENTS.md`, this is not the Next.js in training data. Confirmed from `01-app/02-guides/upgrading/version-16.md`:

| Change | Impact here |
|---|---|
| Turbopack is default for `dev` **and** `build` | No webpack config, ever. A stray webpack option fails the build. |
| `params` / `searchParams` are **Promises**, sync access removed | Every future `[slug]` page must `await props.params`. Use `npx next typegen` → `PageProps<'/services/[slug]'>`. |
| `middleware.ts` → **`proxy.ts`** (nodejs runtime only) | Maintenance-mode rewrite (group 17) uses `proxy.ts`. |
| `next lint` removed | `package.json` already has `"lint": "eslint"`. Correct — leave it. |
| Next no longer overrides `scroll-behavior` on navigation | Do **not** set `scroll-behavior: smooth` or `data-scroll-behavior="smooth"`. Lenis owns scrolling; CSS smooth-scroll would fight it. |
| `images.qualities` defaults to `[75]`, `minimumCacheTTL` 4h | Set `qualities` explicitly in `next.config.ts` if any image needs ≠75. |
| Parallel routes need explicit `default.js` | Not used in Phase 1; noted for future modals. |
| `next dev` outputs to `.next/dev` | Dev and build can run concurrently. |

**Deviations from the brief, and why:**

- **No `/layouts`.** In the App Router, `app/**/layout.tsx` *is* that layer. A parallel `/layouts` folder would be a second source of truth for the same concern. Shared page chrome lives in `components/layout/`.
- **`/components/ui` instead of `/components/common`.** Draws a sharp line: `ui` = zero-domain atoms, `layout` = site chrome. "common" blurs both.
- **`/sections/shared` instead of `/components/home`.** This is the single most important structural choice. Nine of the fourteen Home sections (Services, Industries, Process, Technologies, Case Studies, Testimonials, Stats, FAQ, CTA) reappear on 4–8 of the future pages. Building them as Home-specific components guarantees the refactor the brief forbids. They are built once, prop-driven, and a future Service Detail page composes them from a different data slice.
- **`/data/entities` + `/data/pages` + selectors** instead of flat page data. A service must appear in the header dropdown, the Home grid, the footer list, and its own detail page. One record, many views.

## 3. Animation Strategy

### Division of labour

| Layer | Owns | Rule |
|---|---|---|
| **Lenis** | Page scroll feel only — inertia, damping, wheel/touch normalization | Exactly one instance, at the root. Nothing else touches scroll. |
| **GSAP + ScrollTrigger** | Anything driven by **scroll position** — pins, scrubs, staggered reveals, parallax, counters, headline line-reveals | All timelines live in `/animations`, never inline in TSX. |
| **Motion** (`motion/react`) | Anything driven by **component state** — dropdown, drawer, accordion height, hover/tap, `AnimatePresence`, shared-layout | Never used for scroll-linked work. |

One sentence to keep it honest: **scroll position → GSAP · component state → Motion · scroll feel → Lenis.**

### The Lenis ↔ GSAP bridge (`animations/core/lenis.ts`)

Non-negotiable, and the usual source of janky scrub. Lenis must drive ScrollTrigger, not run beside it:

```
lenis.on('scroll', ScrollTrigger.update)
gsap.ticker.add((t) => lenis.raf(t * 1000))
gsap.ticker.lagSmoothing(0)
```

Wired once inside `SmoothScrollProvider` (a client component in the root layout), so every future page inherits it for free.

### Server-first animation pattern

Sections stay **Server Components**. Markup carries `data-anim="…"` attributes; a thin `'use client'` wrapper (`<ScrollScene scene="process">`) holds the ref, and the GSAP scene selects within that scope via `gsap.context`. Result: complex scroll storytelling with almost no component JS shipped, and section markup remains server-rendered for SEO and LCP.

### Reuse

`/animations/presets` exports parameterized factories (`revealUp({ stagger, distance })`, `splitLines()`, `parallax({ speed })`, `countTo({ value })`). Sections compose presets; only Hero, Process, Stats and Case Studies get bespoke scenes in `/animations/scenes`.

### Reduced motion — three coordinated layers

1. `gsap.matchMedia()` with a `(prefers-reduced-motion: reduce)` branch that **sets final states instantly** rather than skipping setup (skipping would leave elements at `opacity: 0`).
2. `<MotionConfig reducedMotion="user">` wraps the tree — every Motion component respects it automatically.
3. Lenis is **not instantiated** under `reduce`; native scrolling takes over.
4. `styles/motion.css` provides the CSS backstop for anything not JS-driven.

### Performance rules

- Animate `transform` / `opacity` / `filter` only. `will-change` applied on scene enter, removed on complete.
- **LCP protection:** the hero headline is the LCP element. Initial hidden states are applied by a `.js-motion` class that an inline `<head>` script adds only when JS is on *and* motion is allowed. No-JS and reduced-motion users get fully painted text with zero JS dependency.
- Reveal triggers use `once: true`; all scenes are killed via `useGSAP`'s scope cleanup (React 19 StrictMode-safe).
- `content-visibility: auto` + `contain-intrinsic-size` on below-fold sections.
- Marquee (logo strip) runs on a single GSAP tween with `modifiers`, not CSS keyframes on a duplicated DOM — half the nodes, no seam.
- ScrollTrigger `refresh()` debounced on resize and after font load.

## 4. Component Architecture

Four strictly one-directional layers — `ui → shared sections → home sections → page`:

1. **`components/ui`** — atoms. No domain knowledge, no data imports. `Button`, `Container`, `Section`, `SectionHeading`, `Card`, `Accordion`, `Counter`, `Reveal`, `Marquee`, `GradientMesh`.
2. **`components/layout`** — Header, Footer and friends. Mounted once in `app/layout.tsx`; every one of the 17 page groups inherits them with no per-page wiring. Header reads `data/navigation.ts`, so adding a service to `data/entities/services.ts` puts it in the dropdown *and* the footer automatically.
3. **`sections/shared` + `sections/home`** — full-width composites built from `ui` atoms.
4. **`app/page.tsx`** — pure composition. Imports `homePage` from `/data/pages/home.ts`, renders sections in order, passes each its content slice. No literal copy in any TSX file.

### Prop conventions

```ts
// types/common.ts
export interface SectionProps<T> {
  content: T;              // the section's typed data slice — always required
  id?: string;             // anchor target
  className?: string;      // layout escape hatch only
  variant?: SectionVariant // 'default' | 'inverted' | 'compact'
}
```

- One `content` prop per section. Never spread loose props — a new field is a type change in `/types`, which the compiler then enforces at every call site.
- Server Component by default. `'use client'` only in `components/providers`, interactive `layout` pieces, and `ScrollScene`/`Reveal` wrappers.
- Styles: co-located `Component.module.css`. Global CSS is reserved for tokens, reset, typography and utilities.

## 6. Library Recommendations

| Package | Version | Why |
|---|---|---|
| `gsap` | 3.15 | ScrollTrigger has no equal for pinning and scrubbing. Since 3.13 the whole plugin set — **ScrollTrigger, SplitText, Flip** — is free, so the premium headline line-reveals cost nothing. |
| `@gsap/react` | 2.1 | `useGSAP()` — correct cleanup under React 19 StrictMode double-invoke. Doing this by hand is the #1 source of duplicated ScrollTriggers. |
| `lenis` | 1.3 | The scroll feel that separates this tier of site from a corporate template. `lenis/react` ships `ReactLenis` + `useLenis`. Lighter and better-behaved than GSAP ScrollSmoother, which also needs a wrapper/content DOM structure we don't want. |
| `motion` | 12.43 | Framer Motion's current package name (`framer-motion` is the legacy alias at the identical version). Import from `motion/react`. Handles the state-driven work GSAP is clumsy at: `AnimatePresence`, layout animations, accordion auto-height. |
| `lucide-react` | latest | Utility glyphs only — chevron, arrow, search, phone, close. Tree-shakes per icon. |

**Deliberately excluded:**

- **Three.js / R3F** — ~600 kB for a hero background, against an explicit Core Web Vitals requirement. The hero achieves its depth with layered conic/radial gradients, an animated SVG grid, a grain overlay and GSAP parallax — GPU-cheap and it renders on first paint. Revisit only if a specific section genuinely needs 3D; `ogl` (~10 kB) would be the choice.
- **clsx / classnames** — a 5-line `cx()` in `utils/cx.ts` covers every case here.
- **A CSS framework or CSS-in-JS** — excluded by the brief; CSS Modules + custom properties are also simply faster (zero runtime).
- **next-seo** — the native Metadata API plus a small `<JsonLd>` component covers it.
- **Form library** — not needed in Phase 1. The footer newsletter uses a Server Action. When the Contact page arrives: `react-hook-form` + `zod`.
